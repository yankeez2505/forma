# Forma — персональное фитнес-PWA. Спецификация v1

Дата: 2026-10-10. Владелец: Артём. Статус: утверждена (план-режим), дополнена требованием про 3D-модели.

## 1. Цель и контекст

Домашние тренировки под цель (сжечь жир / набрать массу / тонус): опрос + физический тест → персональная программа, короткие эффективные сессии без изнурения, календарь, чекпоинты, аналитика по весу и замерам, рацион из продуктов страны проживания (сначала Беларусь). Хостинг — GitHub Pages: `https://yankeez2505.github.io/forma/`. Сначала для одного пользователя (телефон во время тренировки, ноутбук для аналитики), архитектура — с заделом на подписку.

Личные ограничения владельца, которые программа обязана учитывать:
- перелом голеностопа 02.2026 (пластины) → ударная нагрузка (скакалка, прыжки) заблокирована до чекпоинта;
- история «переборщил на старте → крепатура → бросил» → недели 1–2 RIR 4–5, потолок ≈8 рабочих подходов за сессию, финишер запрещён в блоке 1, авторегуляция по чек-ину.

Инвентарь: гантели 2×10 кг, резинка 15–25 кг, скакалка, коврик, коврик Кузнецова, ролик большой и для стоп, теннисный мяч.

Решения Артёма: Supabase с первого дня; название Forma, репо `forma`; тренировки + аналитика + питание — всё до первого запуска; продукты с привязкой к стране; UI — shadcn/ui + Lucide; **3D-модели спортивного мужчины и девушки показывают упражнения**.

Допущения (не подтверждены): питание v1 = калькулятор КБЖУ + недельные меню + список покупок, без дневника еды. Шаги не считаем (нет трекера) — только рекомендация в тексте программы.

## 4. Auth

Email OTP, 6-значный код, без редиректа: `signInWithOtp({ email })` → `verifyOtp({ email, token, type: 'email' })`; в шаблоне письма Supabase — `{{ .Token }}`. Magic link отклонён: PKCE привязан к браузеру, на iOS ссылка открывается в Safari, а не в PWA. Встроенная почта Supabase — только членам команды проекта, 2 письма/час: владельцу хватает, перед вторым пользователем — свой SMTP (Resend/Brevo). Anon key в клиенте штатно, данные защищает RLS. `.env` не коммитится, ключи — в GitHub Secrets (`VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`).

## 5. Данные

Правила: `id` uuid генерируется на клиенте (идемпотентный upsert); `user_id` денормализован в каждой таблице; RLS `user_id = auth.uid()`; `created_at/updated_at` везде; даты `YYYY-MM-DD` в локальной зоне, `timezone` в профиле.

- `profiles` (id = auth.uid, sex, birth_year, height_cm, country, timezone, goal, experience, days_per_week, session_min, activity_level, injuries jsonb, equipment jsonb, figure: male|female) — веса нет
- `body_metrics` (date, weight_kg, waist_cm, neck_cm, hip_cm; unique(user_id, date))
- `tests` (date, kind: baseline|checkpoint, results jsonb)
- `programs` (start_date, goal, template, config jsonb = снимок анкеты + теста + generator_version + seed, active; partial unique (user_id) where active)
- `planned_sessions` (program_id, date, day_type, exercises jsonb) — только текущий 4-недельный блок; авторегуляция правит следующую сессию
- `workouts` (id, planned_session_id nullable, started_at, finished_at, pre_soreness, pre_sleep, pre_energy, rpe, notes)
- `workout_sets` (id, workout_id, exercise_id = slug, set_no, reps, duration_s, weight_kg, band_kg, rir)
- `nutrition_targets` (date_from, kcal, protein_g, fat_g, carbs_g)

Разблокировка ударной нагрузки не хранится — вычисляется из последнего теста. `subscriptions` добавится позже без ломки схемы.

## 6. Движок программы (`features/program/engine/*`, чистые функции, файлы ≤150 строк)

`types` → `restrictions` (`deriveRestrictions(profile, latestTest)` → `{noImpact, ankleRehab}`) → `pool` (инвентарь ∩ без противопоказаний ∩ уровень; паттерны: присед, тяга-наклон, выпад, жим гор./верт., тяга гор./верт., кор, икры, мобильность) → `templates` (2–3 дня Full-body A/B; 4 дня Upper/Lower) → `baseline` (старт ≈ 50–60 % от максимума теста) → `periodization` (нед. 1–2 RIR 4–5, нед. 3 RIR 3, нед. 4 делоад ≤60 % сетов) → `progression` (двойная прогрессия 8→12, далее вариация по `difficultyRank`; потолок 10 кг) → `autoregulate` (pre-soreness ≥4 → −1 сет, RIR +1, минимум 1 сет) → `warmup` (ankle-блок при `ankleRehab`) → `goals` (жир: финишер без ударки + дефицит; масса: больше сетов, RIR 2, профицит; тонус: поддержка + мобильность) → `generateBlock` (композиция, детерминизм через seed).

Тесты (Vitest):
1. Нога не разблокирована → в блоке ни одного `impact`, включая финишер.
2. Чекпоинт 3/3 (knee-to-wall разница ≤1 см, ≥25 подъёмов на одной ноге, баланс 30 с с закрытыми глазами) → `noImpact=false`; 2/3 → заблокировано.
3. Нед. 1–2 `targetRir ∈ [4,5]`; нед. 4 — сетов ≤60 % от недели 3.
4. 12 повторов во всех сетах две сессии подряд → шаг нагрузки, повторы → 8; один раз → без изменений.
5. 10 кг и все сеты по 12 → следующая вариация в паттерне; нагрузка никогда >10 кг.
6. Домашний инвентарь → ни штанги, ни блоков; каждый слот ≥1 кандидат; вертикальная тяга без турника → явная подмена.
7. 2–3 дня → A-B-A / B-A-B; 4 → U/L/U/L; оценка времени ≤ `session_min`.
8. Pre-soreness ≥4 → −1 сет, RIR +1; soreness ≤2 и RPE ≤6 → без снижения.
9. Одинаковые config+seed+history → идентичный блок; другой seed → другие упражнения в тех же паттернах.
10. Отжимания <5 → с колен/наклонные; ≥20 → стандартные/с гантелями; разминка содержит ankle-блок при `ankleRehab`.

## 7. Тренировка

Черновик `activeWorkout` в Zustand `persist`, клиентские UUID; каждый подход сразу в локальный стор, затем `sync` (`upsert`, флаг `synced`, повтор на `online`/старте/«Завершить»). Черновик удаляется только после подтверждённого завершения («Продолжить тренировку?»). Таймер по `Date.now()` + `navigator.wakeLock`. Чек-ин (боль/сон/энергия) — в начале следующей сессии (пик крепатуры 24–72 ч), RPE — после.

## 8. Визуал упражнений

- **3D-демо** (требование Артёма): персонаж выполняет упражнение в цикле; пол персонажа — в профиле (по умолчанию = пол пользователя), переключатель на экране упражнения.
  - v1 (без внешних аккаунтов и лицензионных рисков): процедурный стилизованный персонаж на react-three-fiber — капсульный «атлет» с двумя наборами пропорций (male/female), фирменные цвета, студийный свет, тень. Анимация = ключевые позы суставов в `content-src/anims/<slug>.json` (углы Эйлера по 14 суставам + положение корня), интерполяция с плавностью, цикл. Приоритет — упражнения из программы владельца.
  - Апгрейд (нужен Артём): персонажи и анимации Mixamo (бесплатно, Adobe-аккаунт; ≈20 упражнений в библиотеке) → GLB → тот же компонент через `useAnimations`; остальные упражнения — Rokoko Vision (AI-мокап по видео с телефона) или покупной пак фитнес-анимаций. Контракт компонента не меняется: `<ExerciseFigure slug figure="male|female" />`.
- **Фото** из free-exercise-db (Unlicense, 2 кадра на упражнение, WebP 600px) — вторая вкладка и fallback там, где нет анимации.
- Переводы отдельно: `i18n/exercises.ru.json` `{slug: {name, cues[], reviewed}}`; скрипт сборки не перезаписывает, только сообщает о пропусках. Валидация сборки: все slug переведены, уникальный `difficultyRank` внутри паттерна, ≥2 кандидата на паттерн для домашнего инвентаря.
- Мышцы: группы-бейджи + подсветка на схеме (своя SVG-схема, если `react-body-highlighter` не встанет на React 19).

## 9. Питание и аналитика

- Mifflin-St Jeor → TDEE (активность + тренировочные дни) → жир −15–20 %, масса +5–10 %, тонус 0. Белок 1,6–2,2 г/кг, жиры 0,8–1 г/кг, углеводы — остаток.
- `foods.json` ≈100 позиций с `countries: ['BY']` (творог, кефир, гречка, овсянка, яйца, куриное филе, индейка, минтай/хек, сельдь, картофель, свёкла, капуста, морковь, яблоки, ржаной хлеб; Савушкин, Бабушкина крынка, Санта Бремор, Петруха), макросы по USDA/Open Food Facts. 3 шаблона меню (дефицит/профицит/поддержка), порции масштабируются к цели, список покупок на неделю.
- Аналитика: вес (среднее за 7 дней), талия, ИМТ, жир по формуле ВМС США, подходы/неделю на группу мышц, динамика тестов, план/факт, стрик.
- Медицинский дисклеймер у критериев разблокировки и у программы.

## 11. Верификация

- `npm test` зелёный на каждом коммите; `npm run build` без ошибок; деплой на Pages после каждого этапа.
- Показ: десктоп — Playwright в развёрнутом окне (1707 CSS, DPR 1.5); мобильная версия — отдельно и с пометкой.
- Сквозной сценарий v1: вход по коду → онбординг + тест → 4-недельный блок в календаре → тренировка с логом офлайн → после включения сети данные в Supabase → чек-ин → ретест на чекпоинте → графики → питание показывает цель и меню.
